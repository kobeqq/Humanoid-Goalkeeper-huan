# 全向移动 V1：K1 Command-Conditioned AMP 框架说明

本文档对应当前仓库中的 `k1_loco_amp` 任务。它是一个面向 K1 人形机器人的全向下肢移动任务：策略接收机体状态、关节状态、历史信息、速度命令和步态相位，输出 12 维下肢动作；环境使用 PD 控制器把动作转换为 22 个关节的力矩；同时使用 AMP（Adversarial Motion Priors）让机器人动作接近按命令选择的专家运动。

## 1. 总体特点和核心技术

### 1.1 任务定位

`k1_loco_amp` 的核心不是“直接模仿一条固定动作”，而是：

```text
速度命令 (vx, vy, wz)
        |
        v
Actor-Critic 策略 ---> 12 维下肢动作 ---> PD 控制 ---> K1 物理仿真
        ^                                      |
        |                                      v
        +--- 10 帧历史观测 <--- 环境状态、奖励、AMP 状态

命令类别 ---> 对应专家运动库 ---> AMP 判别器 ---> AMP 奖励
```

### 1.2 主要技术方法

| 技术 | 当前实现 | 作用 |
|---|---|---|
| PPO | `HIMPPO` | 根据 rollout 中的奖励更新 Actor 和 Critic |
| AMP | `rsl_rl/modules/amp.py` | 区分专家动作状态和策略动作状态，并提供模仿奖励 |
| Command-conditioned AMP | `command_motion_map` + `amp_motion_ids` | 不同移动命令使用不同专家运动 |
| History encoder | 650 维历史观测 -> 16 维 latent | 从历史中提取速度、接触和动作变化等隐含信息 |
| PD position control | `q_target = q_default + action_scale * action` | 策略输出关节目标偏移，而不是直接输出 torque |
| 域随机化 | 摩擦、质量、质心、PD 增益、执行器扰动等 | 增强对真实机器人动力学变化的鲁棒性 |
| 下肢动作映射 | 12 维策略动作映射到 22 DOF 中的腿部关节 | 上肢保持默认姿态，第一阶段只学习下肢移动 |

当前任务继承关系为：

```text
BaseTask
  -> LeggedRobot
      -> LeggedRobotMoveAmp2D
          -> LeggedRobotK1LocoAmp
```

配置继承关系为：

```text
LeggedRobotCfg
  -> K122Cfg
      -> K1MoveAmpCfg
          -> K1LocoAmpCfg

K1LocoAmpCfgPPO
  -> K1MoveAmpCfgPPO
      -> K122CfgPPO
```

## 2. 任务规模和关键维度

当前配置中的关键维度如下：

| 参数 | 数值 | 含义 |
|---|---:|---|
| `num_envs` | 4096 | 并行仿真的环境数量 |
| `num_dofs` | 22 | K1 的全部关节数 |
| `num_actions` | 12 | 策略控制的左右腿关节数 |
| `num_command_obs` | 5 | 归一化后的 `(vx, vy, wz)` 三维命令 + `sin(phase), cos(phase)` |
| `num_one_step_observations` | 65 | 当前时刻单帧 actor 观测 |
| `num_actor_history` | 10 | 历史帧数 |
| `num_observations` | 650 | `10 * 65`，Actor 输入的历史观测 |
| `num_privileged_obs` | 68 | 65 维 actor 单帧观测 + 3 维机体线速度 |
| `amp.num_obs_per_step` | 32 | 一帧 AMP 状态 |
| `amp.num_steps` | 2 | AMP 使用连续两帧 |
| `num_amp_obs` | 64 | `2 * 32`，判别器输入 |
| `num_steps_per_env` | 32 | 每轮每个环境收集的策略交互步数 |
| `num_mini_batches` | 8 | PPO 更新时把 rollout 划分成 8 个 mini-batch |
| `num_learning_epochs` | 3 | 同一轮 rollout 重复训练 3 遍 |

因此一轮 rollout 的原始交互样本数为：

\[
N_{rollout}=4096 \times 32=131072.
\]

当前 `HIMRolloutStorage.mini_batch_generator()` 使用 `[:-1]`，因此真正参与更新的样本数为：

\[
N_{update}=4096 \times (32-1)=126976,
\]

每个 mini-batch 的大小为：

\[
N_{mini}=126976/8=15872.
\]

每轮 PPO/AMP 更新次数为：

\[
3 \times 8=24.
\]

## 3. 观测设计

### 3.1 Actor 单步观测：65 维

`LeggedRobotK1LocoAmp._build_actor_one_step_obs()` 的拼接顺序为：

| 顺序 | 内容 | 维度 | 说明 |
|---:|---|---:|---|
| 1 | 归一化命令 | 3 | `vx / max_vx`, `vy / max_vy`, `wz / max_wz` |
| 2 | 步态相位 | 2 | `sin(gait_phase)`, `cos(gait_phase)` |
| 3 | 机体角速度 | 3 | `base_ang_vel * obs_scales.ang_vel` |
| 4 | 投影重力 | 3 | 在机体坐标系中的重力方向 |
| 5 | 关节位置偏差 | 22 | `(dof_pos - default_dof_pos) * obs_scales.dof_pos` |
| 6 | 关节速度 | 22 | `dof_vel * obs_scales.dof_vel` |
| 7 | 上一动作 | 12 | `self.actions` |
|  | 合计 | **65** | `5 + 3 + 3 + 22 + 22 + 12` |

这里的命令不是简单的离散标签。命令采样先从以下类别中采样，再在对应范围内采样连续速度：

| 命令类别 | 概率 | `vx` 范围 | `vy` 范围 |
|---|---:|---:|---:|
| standing | 0.12 | 0 | 0 |
| forward | 0.22 | 0.20 ~ 0.35 | -0.04 ~ 0.04 |
| backward | 0.17 | -0.32 ~ -0.18 | -0.04 ~ 0.04 |
| leftstep | 0.16 | -0.04 ~ 0.04 | 0.18 ~ 0.32 |
| rightstep | 0.16 | -0.04 ~ 0.04 | -0.32 ~ -0.18 |
| diagonal_left | 0.08 | 0.18 ~ 0.32 | 0.12 ~ 0.28 |
| diagonal_right | 0.08 | 0.18 ~ 0.32 | -0.28 ~ -0.12 |

命令每 5 秒重新采样一次。当前 `train_yaw_command=False`，所以训练时 `wz=0`，但观测仍保留 3 维命令接口。

### 3.2 Actor 历史观测：650 维

环境中的 `obs_buf` 保存最近 10 个单步观测：

\[
o_t^{hist}=[o_{t-9},o_{t-8},...,o_t]\in\mathbb{R}^{650}.
\]

历史信息可以帮助策略推断单帧中没有直接给出的动态信息，例如：

- 关节速度和机体角速度的变化趋势；
- 左右脚的交替运动阶段；
- 过去动作导致的延迟响应；
- 接触和身体姿态的短期变化。

`_get_noise_scale_vec()` 只对传感器类观测加噪声。命令、角速度、投影重力、关节位置和关节速度可以加噪声；步态相位是确定性的内部时钟，不加噪声；上一动作也不加噪声。

### 3.3 Critic 特权观测：68 维

Critic 使用：

\[
s_t=[o_t, v^B_t]\in\mathbb{R}^{68},
\]

其中 `o_t` 是 65 维 actor 单帧观测，`v^B_t` 是机体坐标系中的 3 维线速度。当前实现中 actor 观测没有直接看到真实线速度，而 Critic 可以看到它。

这样做符合 asymmetric actor-critic 的思想：训练时 Critic 使用更完整的状态估计价值函数，帮助降低 advantage 方差；部署时只使用 Actor 的可观测量，不依赖仿真中的 privileged 信息。

### 3.4 AMP 观测：64 维

`get_amp_observations()` 先选择 12 个下肢关节，再由 `build_lower_body_amp_step_obs()` 构造单帧 32 维状态：

| 内容 | 维度 |
|---|---:|
| 下肢关节位置 `q_leg` | 12 |
| 下肢关节速度 `dq_leg` | 12 |
| 机体线速度 XY | 2 |
| 机体角速度 | 3 |
| 投影重力 | 3 |
| 合计 | **32** |

这里的线速度只取机体坐标系中的 XY 平移速度，不包含竖直方向速度，因此单帧确实是 32 维，与 `num_obs_per_step=32` 一致。`base_lin_vel[:, :2]` 的实现也体现了 AMP 主要关注平面移动。

AMP 使用当前帧和下一帧拼接：

\[
x_t^{amp}=[a_t,a_{t+1}]\in\mathbb{R}^{64}.
\]

判别器输入的是运动状态序列，不是 actor 的 650 维历史观测。AMP 的目标是判断短时间动作是否像专家，而不是直接替代 PPO 的任务奖励。

## 4. 动作和 PD 控制

### 4.1 12 维动作到 22 DOF

`_init_lower_body_action_mapping()` 根据配置中的 `left_leg_joints + right_leg_joints` 查找这些关节在 `dof_names` 中的索引：

```python
lower_ids = [self.dof_names.index(name) for name in lower_names]
upper_ids = [idx for idx in range(self.num_dof) if idx not in set(lower_ids)]
```

因此：

- 策略输出 `actions.shape = [num_envs, 12]`；
- 12 个值被写入 22 DOF 的下肢位置目标；
- 非下肢关节使用默认姿态目标；
- 头部、肩部和手臂在第一阶段主要由 PD 控制器保持默认姿态。

### 4.2 Position control 公式

当前 `control_type='P'`，动作缩放和目标位置为：

\[
q^{target}=q^{default}+s_a a,
\]

其中 `s_a = action_scale`，`a` 是策略输出。随后 PD 控制器计算：

\[
\tau_{PD}=K_p(q^{target}-q)-K_d\dot q.
\]

考虑域随机化和执行器扰动后，代码近似为：

\[
\tau=K_p f_{K_p}(q^{target}-q)-K_d f_{K_d}\dot q
       +\tau_{offset}+\tau_{injection}.
\]

最后进行力矩裁剪：

\[
\tau=clip(\tau,-\tau_{max},\tau_{max}).
\]

因此策略输出的是“关节目标位置偏移”，不是直接 torque。这样能把低层稳定控制交给 PD，策略主要学习步态、支撑和关节目标变化。

每个策略步内部还会执行 `decimation=4` 个仿真控制子步，因此 32 个策略步大约对应 128 个物理子步；`num_steps_per_env=32` 不等于物理引擎只运行 32 次。

## 5. 奖励函数

总的 raw reward 是各项奖励的加权和：

\[
r_t^{raw}=\sum_i w_i r_i(s_t,a_t,s_{t+1}).
\]

当前任务 `only_positive_rewards=False`，所以负奖励不会被裁剪为零。

### 5.1 任务奖励

| 奖励 | 代码公式/数学形式 | 权重 | 训练目的 |
|---|---|---:|---|
| 线速度跟踪 | `e_v=||c_{xy}-v_{xy}||^2`, `exp(-e_v/sigma)` | 4.5 | 沿命令方向和速度移动 |
| 角速度跟踪 | `e_w=(c_w-w_z)^2`, `exp(-e_w/sigma)` | 0.1 | 为未来转向提供接口，当前 yaw command 通常为 0 |
| upright | 依赖 `projected_gravity`，鼓励身体保持竖直 | 1.0 | 防止摔倒、侧倾 |
| height | 身体高度与目标高度的高斯型误差 | 0.5 | 保持合理躯干高度 |
| stand_still | 静止命令下 `exp(-||dq_leg||^2*sigma)` | 0.3 | standing 时不要无意义抖腿 |
| gait_phase | 左右脚相对高度与 `sin(phase)` 的误差 | 0.5 | 形成有节奏的交替步态 |

线速度跟踪的数学形式为：

\[
r_{lin}=\exp\left(-\frac{\|(v_x^c,v_y^c)-(v_x,v_y)\|^2}{\sigma_v}\right),
\quad \sigma_v=0.14.
\]

角速度跟踪为：

\[
r_{ang}=\exp\left(-\frac{(\omega_z^c-\omega_z)^2}{\sigma_\omega}\right),
\quad \sigma_\omega=0.25.
\]

静止奖励只在 `||command_xy|| < 0.05` 时激活。步态相位奖励在速度低于 `0.06 m/s` 时基本关闭，并随速度增加逐渐打开，因此不会强迫机器人原地踏步。

### 5.2 正则项和约束项

| 项 | 数学含义 | 权重 | 过大时的风险 |
|---|---|---:|---|
| `feet_slip` | 接触脚速度平方惩罚 | -0.05 | 脚步变得保守，可能拖脚或不敢迈步 |
| `ang_vel_xy` | `-(\omega_x^2+\omega_y^2)` | -0.03 | 限制身体滚转/俯仰，但太大导致僵硬 |
| `dof_acc` | `-||\ddot q||^2` | -2.5e-7 | 抑制高频关节加速度 |
| `smoothness` | 主要惩罚动作一阶/二阶变化 | -0.004 | 动作更平滑，但过大使响应迟钝 |
| `torques` | `-||\tau||^2` | -1e-5 | 降低能耗和峰值力矩 |
| `dof_vel` | `-||\dot q||^2` | -5e-4 | 限制关节高速运动 |
| `dof_pos_limits` | 超过软位置边界的量 | -1.5 | 避免关节撞限位 |
| `dof_vel_limits` | 超过软速度边界的量 | -0.1 | 避免超速 |
| `torque_limits` | 接近/超过力矩上限的惩罚 | -0.2 | 避免长期饱和 |

这些正则项不是越大越好。任务奖励太小会导致机器人“站得很稳但不走”；跟踪奖励太大而正则太小会导致动作猛、耗能高、关节接近限位；平滑项太大则常见表现是小碎步、跟不上命令或响应滞后。

## 6. AMP 数据和 command-conditioned 模仿

### 6.1 数据加载和过滤

数据目录为：

```text
legged_gym/resources/datasets/goalkeeper_from_pkl_k1_locomotion
```

`_reinit_amp_motions_for_lower_body()` 执行以下工作：

1. `load_imitation_dataset()` 读取数据和关节映射；
2. 对数据集中的每个 motion key 构造 `MotionLib`；
3. 根据 `dataset.motion_weights` 过滤权重为 0 的类别；
4. 对保留下来的类别按权重归一化，形成 AMP motion 采样概率；
5. 根据 `command_motion_map` 建立命令类别到专家 motion 的映射。

当前权重为：standing=0.15，forward/backward/leftstep/rightstep/diagonal=1.0；`dive_jump` 和 `turn_or_yaw_heavy` 权重为 0，不参与当前 locomotion AMP。

### 6.2 命令到专家动作

当前映射为：

| 命令 | AMP motion |
|---|---|
| standing | standing |
| forward | forward |
| backward | backward |
| leftstep | leftstep |
| rightstep | rightstep |
| diagonal_left | diagonal |
| diagonal_right | diagonal |

环境保存 `command_type_ids`。`get_amp_motion_ids()` 返回这些 id，runner 将其一起写入 rollout storage。AMP 更新时，判别器从对应 motion buffer 中抽取专家片段，而不是把所有方向的专家混在一起：

\[
x_t^{expert}=MotionLib_{m(command_t)}.sample(),
\]

这就是 command-conditioned AMP 的关键。

### 6.3 AMP 判别器和模仿奖励

判别器输入 64 维 AMP 状态，输出一个标量 logit：

\[
D(x)=MLP_{AMP}(x)\in\mathbb{R}.
\]

代码使用 least-squares 风格损失：

\[
L_E=\mathbb{E}[(D(x_E)-1)^2],
\]

\[
L_P=\mathbb{E}[(D(x_P)+1)^2],
\]

\[
L_{AMP}=L_E+L_P+L_{grad}.
\]

策略状态的 AMP 奖励由判别器输出构造，当前 runner 中先乘以 0.5，再与 raw reward 混合。`reward_mode="mixture"` 时：

\[
r_t=(1-\alpha)r_t^{raw}+\alpha r_t^{amp},
\quad \alpha=amp\_coef=0.20.
\]

也就是当前约为：

\[
r_t=0.8r_t^{raw}+0.2r_t^{amp}.
\]

AMP 负责“像不像专家”，任务奖励负责“是否完成速度命令并保持稳定”。两者互补。

## 7. Actor-Critic 网络

### 7.1 History encoder

Actor 输入的 650 维历史先经过：

```text
650 -> Linear(128) -> ReLU -> Linear(64) -> ReLU -> Linear(16)
```

得到历史 latent：

\[
h_t=f_{hist}(o_t^{hist})\in\mathbb{R}^{16}.
\]

当前 `estimate_ball_dim=0`，所以没有 ball estimator，也不会额外预测球的位置。Actor 最终输入是：

\[
[o_t,h_t]\in\mathbb{R}^{65+16}=\mathbb{R}^{81}.
\]

### 7.2 Actor 和 Critic

当前配置继承的隐藏层为 `[512,256,256]`，因此：

```text
Actor: 81 -> 512 -> 256 -> 256 -> 12
Critic: 68 -> 512 -> 256 -> 256 -> 1
```

Actor 最后一层输出动作均值 `mu`。策略使用固定形式的对角高斯分布：

\[
a_t\sim\mathcal{N}(\mu_\theta(o_t),diag(\sigma_\theta^2)),
\]

其中 `std` 是一个可学习的 12 维 `nn.Parameter`。训练时调用 `distribution.sample()` 产生探索动作；推理时调用 `act_inference()`，使用 `mu` 作为确定性动作，减少随机性。

Critic 输出状态价值：

\[
V_\phi(s_t)\in\mathbb{R}.
\]

## 8. Rollout 收集

一轮训练的主流程为：

```text
当前 obs / critic_obs
        |
        v
ActorCritic.act()
        |
        v
采样 12 维 action，同时得到 value、log_prob、mu、sigma
        |
        v
env.step(action)
        |
        +--> PD + 4 个物理子步 + post_physics_step
        |
        +--> raw reward、done、next obs、next privileged obs
        |
        +--> 当前 AMP 状态，与上一帧拼成 64 维 AMP state
        |
        +--> 判别器给出 AMP reward
        |
        v
混合 reward 写入 HIMRolloutStorage
```

每个 transition 保存：

- actor observation；
- privileged critic observation 和 next critic observation；
- action；
- 混合后的 reward；
- done；
- old value；
- old action log probability；
- old action mean/std；
- AMP observation；
- command 对应的 `amp_motion_id`。

`num_steps_per_env=32` 表示每个并行环境完成 32 次“策略决策 -> 环境响应”。因为有 4096 个环境，所以一次 rollout 同时得到 `4096*32=131072` 个交互样本；mini-batch 生成器由于使用 `[:-1]`，真正更新的样本数是 `4096*31=126976`。

## 9. GAE、PPO 和网络更新

### 9.1 GAE 和 return

对每个时间步，TD 残差为：

\[
\delta_t=r_t+(1-d_t)\gamma V(s_{t+1})-V(s_t).
\]

GAE 反向递推：

\[
A_t=\delta_t+(1-d_t)\gamma\lambda A_{t+1}.
\]

return 为：

\[
R_t=A_t+V(s_t).
\]

代码随后对 advantage 做 batch 标准化：

\[
\hat A_t=\frac{A_t-mean(A)}{std(A)+10^{-8}}.
\]

### 9.2 PPO clipped surrogate loss

旧策略和新策略的概率比为：

\[
ratio_t=\exp(\log\pi_\theta(a_t|s_t)-\log\pi_{old}(a_t|s_t)).
\]

PPO 的策略目标是：

\[
L^{clip}=\mathbb{E}\left[\max\left(-ratio_t\hat A_t,
-clip(ratio_t,1-\epsilon,1+\epsilon)\hat A_t\right)\right].
\]

当前 `clip_param=0.2`。裁剪的目的，是避免一次更新把策略改变得过大。

### 9.3 Value loss 和 entropy

Critic 的基本损失为：

\[
L_V=\mathbb{E}[(R_t-V_\phi(s_t))^2].
\]

如果启用 value clipping，则对新旧 value 的变化也限制在 `[-0.2,0.2]` 范围附近。

策略熵为高斯分布熵：

\[
H(\pi)=\sum_j H(\mathcal{N}(\mu_j,\sigma_j^2)).
\]

总的 Actor-Critic 优化目标近似为：

\[
L=L^{clip}+c_VL_V-c_HH+L_{est}+L_{smooth}+L_{AMP}.
\]

`-entropy_coef * entropy` 使最大化熵等价于在最小化损失时减去熵，鼓励训练早期探索。

### 9.4 KL 自适应学习率

代码根据新旧高斯策略的 KL 散度调整学习率：

\[
KL(\pi_{old}||\pi_{new})
=\sum_j\left[\log\frac{\sigma_j}{\sigma_j^{old}}
 +\frac{(\sigma_j^{old})^2+(\mu_j^{old}-\mu_j)^2}{2\sigma_j^2}-\frac12\right].
\]

当 KL 大于目标值的两倍时降低学习率；当 KL 小于目标值的一半时提高学习率。目的，是让策略更新既不会过激，也不会过于保守。

### 9.5 Smoothness loss

代码在同一个 mini-batch 中对连续状态做插值：

\[
\tilde o=o+\eta(o_{next}-o),
\quad \eta\sim Uniform(-1,1).
\]

然后约束原状态和插值状态的策略输出、价值输出不要差异过大：

\[
L_{policy-smooth}=||\mu(o)-\mu(\tilde o)||^2,
\]

\[
L_{value-smooth}=||V(s)-V(\tilde s)||^2.
\]

这是一种局部 Lipschitz 正则化，作用是减少策略对观测噪声和微小动力学变化的敏感性。

### 9.6 AMP 更新

每个 PPO mini-batch 内：

1. 根据 `amp_motion_id_batch` 从对应 `MotionLib` 采样专家 AMP 状态；
2. 对策略 AMP 状态和专家 AMP 状态使用同一个 AMP normalizer；
3. 计算 `expert_loss`、`policy_loss` 和 gradient penalty；
4. 将 AMP loss 加入总 loss；
5. 通过反向传播更新 Actor-Critic 参数；
6. AMP 判别器的参数由 AMP 优化器更新。

这里的重点是，AMP 不是 rollout 后单独运行一次，而是跟随 PPO 的 mini-batch 更新节奏参与当前轮训练。

## 10. 域随机化

当前 `K1LocoAmpCfg.domain_rand` 启用的随机因素包括：

| 随机项 | 范围 | 影响 |
|---|---|---|
| joint injection | -0.005 ~ 0.005 | 模拟关节扰动力矩 |
| actuation offset | -0.005 ~ 0.005 | 模拟执行器偏置 |
| payload mass | -0.5 ~ 1.0 | 改变额外负载 |
| COM displacement | -0.02 ~ 0.02 | 改变质心位置 |
| link mass | 0.9 ~ 1.1 倍 | 改变各连杆质量 |
| friction | 0.6 ~ 1.5 | 改变接触摩擦 |
| Kp factor | 0.9 ~ 1.1 | 改变位置增益 |
| Kd factor | 0.9 ~ 1.1 | 改变速度阻尼 |
| action delay | enabled | 模拟控制延迟 |

随机化的目的不是让训练更难，而是让策略不要只适应一个精确的仿真模型。理想目标是：

\[
\pi(a|o;\xi)\text{ 在一组动力学参数 }\xi\text{ 上都保持稳定。}
\]

## 11. 一轮完整训练闭环

```text
1. 读取 obs_buf(650) 和 privileged_obs(68)
2. History encoder: 650 -> 16
3. Actor 拼接当前 65 维 + 16 维 latent，输出 12 维动作均值
4. 训练时从 Normal(mu, std) 采样 action
5. 12 维下肢动作映射到 22 DOF，非下肢维持默认姿态
6. action_scale 转成关节目标偏移
7. PD 计算 torque，执行 4 个物理子步
8. 更新状态、命令、步态相位和历史观测
9. 计算 tracking/upright/height/gait/regularization 等 raw reward
10. 取当前和下一帧 AMP 状态，组成 64 维输入
11. 根据命令类别取对应专家 motion，判别器计算 AMP reward
12. 混合 raw reward 和 AMP reward，写入 storage
13. 重复 32 个策略步
14. 用最后一个 critic value 计算 GAE、return 和 normalized advantage
15. 把 rollout 的前 31 个时间位置展平，分成 8 个 mini-batch
16. 重复 3 个 learning epochs，共 24 次 mini-batch 更新
17. 更新 Actor、Critic 和 AMP discriminator
18. 保存日志、checkpoint，进入下一轮 rollout
```

## 12. 最值得优先检查的风险点

1. 观测维度必须始终一致：65、650、68 和 64 分别对应 actor 单帧、actor 历史、critic 和 AMP 输入。
2. AMP 单帧实际拼接维度要和 `num_obs_per_step=32` 一致，否则会在 storage 或 discriminator 处出错。
3. `command_type_ids` 必须与 `command_motion_map`、motion buffer 名称一致，否则会取到错误专家动作。
4. 12 维动作和 22 个 DOF 的索引顺序必须一致；错误的关节名字会导致动作控制错腿或错关节。
5. 当前 `num_steps_per_env=32` 的更新样本实际使用 `[:-1]`，因此计算 batch size 时是 31 而不是 32；如果切换到其他配置，必须重新计算。
6. AMP reward 的量级必须和 raw reward 对比检查；AMP 权重太大可能只模仿专家而不跟踪命令，太小则 AMP 约束几乎不起作用。
7. 域随机化范围过大可能导致训练初期无法站立，范围过小则 sim-to-real 泛化不足。
